# BFO–CCO Design Pattern Application Checklist

Use this checklist to confirm correct application of **BFO–CCO standards** and **established design patterns** when modeling.

---

## Before Modeling
- [ ] I identified the relevant **BFO category** (e.g., continuant vs occurrent).
- [ ] I checked whether an existing **CCO or CUBRC design pattern** applies.
- [ ] I reviewed prior examples instead of inventing a new structure.

---

## During Modeling
- [ ] I used the established design pattern **without altering its core structure**.
- [ ] I applied relations exactly as defined in BFO–CCO.
- [ ] I represented **dates, roles, and identifiers** using approved patterns.
- [ ] I used consistent **labels, IRIs, and annotations**.

---

## After Modeling
- [ ] The model aligns with **BFO–CCO constraints**.
- [ ] The design pattern used matches existing SKS / CCO examples.
- [ ] Another ontologist could immediately recognize the pattern used.

---

## Example: Birth Date Representation

- [ ] I modeled birth as a **process/event**, not as a data property of a person.
- [ ] The **temporal information** is attached to the process, not the entity.
- [ ] The person is correctly related to the birth process via participation.
- [ ] The model follows established **CCO/CUBRC birth-date patterns**.

---

## Associate-Level Confirmation
- [ ] I reused an approved pattern rather than creating a custom solution.
- [ ] I can explain **why** this pattern is correct in BFO–CCO terms.
